# 旁白脚本 · 智能体与运行系统（审阅稿 v1）

- 写给耳朵听，不是给眼睛读。短句，口语，先说中文，英文术语只在第一次出现时跟在后面。
- 全文约 720 个汉字。按 4.4 字/秒估算约 3:10。**这是估算**：最终分镜时长以生成好的配音为准。
- 每个场次编号对应 `storyboard.html` 里的一行。
- 「」里是屏幕上会出现的关键字，旁白不逐字重复屏幕文字。

---

**S1 钩子（0:00–0:06）**
AI 明明说它会，为什么一动手，就出问题？

**S2 具体任务（0:06–0:21）**
拿一个具体任务来说：把 20 份 PDF 整理成一张索引表，原文件不能动。
在聊天框里问，AI 会列出五个步骤，头头是道。
可你要的不是方法，是一个能打开的表格。

**S3 大模型 Model（0:21–0:37）**
先看核心：大模型，Model。
它看到任务、已有的信息和可用的工具，然后提出下一步，比如“列出文件夹里的文件”。
注意，这只是一个请求，还没有任何文件被打开。

**S4a 运行与控制系统 Harness（0:37–0:52）**
谁来执行？是模型外面这一层：运行与控制系统，英文叫 Harness。
它把工具交给模型，收到请求先检查、再执行，然后把结果送回去。

**S4b 循环 ＝ 智能体 Agent（0:52–1:09）**
结果：文件夹里有 20 份 PDF。模型据此决定下一步：读第一份。
请求、执行、结果、再决定。
能根据结果一步步走向目标的整个系统，就是智能体，Agent。
如果每一步都提前写死，那是固定流程，不算这里说的智能体。

**S5 循环跑起来（1:09–1:14）**
第一份、第二份……索引表一行一行长出来。

**S6 失败与恢复（1:14–1:32）**
读到第 8 份，出错了：文件打不开。
系统先把错误记下来，标成“待处理”。
模型换一个允许的办法，用文字识别再试，还是不行。
那就留给人来判断，先做剩下的。失败的那份，一直摆在明面上。

**S7 权限关卡（1:32–1:59）**
这时模型提议：“第 8 份坏了，删掉吧。”
你可能在提示词里写过“请小心，别动原文件”。但那只是一句话，模型可能照做，也可能理解偏。
真正拦住它的，是运行系统里的规则：原文件夹只读。删除请求在这里被拒，碰不到硬盘。
前提是，这条规则真的配置了，不是每个产品默认都这样。

**S8 上下文 vs 进度记录（1:59–2:25）**
任务一长，还有个问题：模型一次能看的内容有限，这叫上下文，Context。
早先的细节会被挤掉，换个新会话更是从头来。
所以系统把进度写进文件：哪 19 份做完了，哪份卡住、为什么，下一步做什么。
重新开始先读记录，就能接着干。这不是完美记忆，只有写下来的才找得回。

**S9 验证（2:25–2:48）**
最后，表格保存成功。
但“保存成功”只说明文件写出来了，不代表内容对。
拿输入清单和输出表对一遍：进来 20 份，写好 19 行，1 份待处理。再抽查几行标题和页数。
诚实的汇报是：“完成 19 份，1 份需要你看。”而不是“20 份全部搞定”。

**S10 三句话（2:48–3:00）**
记住三句话：模型提出下一步；运行系统负责执行、拦截和记录；结果要检查过才算数。

**S11 小测验（3:00–3:10）**
考你一题：如果模型想删原文件，真正该拦住它的是什么？
（停 2 秒，画面静止）
答案：运行系统里强制执行的权限规则，不是一句“请小心”。

## 配音注意（给 TTS 和人工复核用）

| 词 | 读法 / 处理 |
|---|---|
| PDF | 按英文字母读 “P-D-F” |
| Model / Harness / Agent / Context | 英文读，前后各留一个短停顿；如果本地 TTS 读得别扭，就改成只读中文，英文只留在屏幕上 |
| 20 份 / 19 份 / 第 8 份 | 读作“二十份 / 十九份 / 第八份”；需要的话在 TTS 输入里直接写汉字数字 |
| list_files、read_pdf、delete | **不读**，只出现在屏幕上 |
| “请小心” | 语气轻一点，和后面“规则”的语气形成对比 |
| S11 停顿 | 问题之后画面静止 2 秒，再揭示答案 |
